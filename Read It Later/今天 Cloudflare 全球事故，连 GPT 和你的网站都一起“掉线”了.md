# 今天 Cloudflare 全球事故，连 GPT 和你的网站都一起“掉线”了

[![[Read It Later/attachments/d69cc3fa3131b67f7220e9295dcacb8b_MD5.jpg]]](https://www.zhihu.com/people/zhi-ta-hu-wo)

[我爱算法](https://www.zhihu.com/people/zhi-ta-hu-wo)

今天 Cloudeflare 挂了，其实很多人都“躺枪”了。

当你刷着社交媒体、打开博客、访问网站的时候，发现页面卡住、提示 500 错误、或者直接 “访问失败”，这不是你的网线出了问题，而是男主角登场了：[Cloudflare](https://zhida.zhihu.com/search?content_id=266557689&content_type=Article&match_order=1&q=Cloudflare&zhida_source=entity)。

根据最新报道，Cloudflare 的全球网络正在遭遇技术障碍——多个平台、网站及服务一起受波及，连 [ChatGPT](https://zhida.zhihu.com/search?content_id=266557689&content_type=Article&match_order=1&q=ChatGPT&zhida_source=entity)、推特、Cladude 等等都躲不过～

![[Read It Later/attachments/c26f7bb4e0c7fd598b7baf0d64234e4a_MD5.jpg]]

为什么“中招”这么多人？因为 Cloudflare 本身就是 “中枢”之一。它负责的网站加速、内容分发、[DNS解析](https://zhida.zhihu.com/search?content_id=266557689&content_type=Article&match_order=1&q=DNS%E8%A7%A3%E6%9E%90&zhida_source=entity)、安全防护——换句话说，它帮成千上万的网站在世界各地更快速、更安全地“上线”。而当这个“枢纽”出现问题，连锁反应几乎瞬时扩散。

比如，ChatGPT 就被用户报告 “请取消阻止 [http://challenges.cloudflare.com](https://link.zhihu.com/?target=http%3A//challenges.cloudflare.com) 后继续”。 再比如，一些博客、个人网站甚至客户端服务，都可能因为 Cloudflare 的网络中断而直接“打不开网页”或“访问延迟严重”。

![[Read It Later/attachments/591f859ea4d270aab9ee646bf4a4f2a9_MD5.jpg]]

这提醒我们两个现实：

1. **互联网依赖度极高**。我们平时并不觉得连接了多少“中介服务”，但其实你访问的某个网站，背后很可能借助了 Cloudflare 这样的“隐形网络服务商”。当它出问题，你我都中招。
2. **风险并非只在“黑客”或“攻击”层面**。很多时候，出问题的是基础网络设施、节点故障、数据中心切换、配置误操作……不是谁“故意”要让你上不了网，而是“链条”中某一环出了状况。

那么，对普通用户来说，遇到这种情况怎么办？简单三步：

- 放松——不是你的设备、不是你犯错了，只是他们的服务暂时“挂了”。
- 刷新状态页面、社交公告。Cloudflare 官方在其状态页已说明：他们“意识到问题，正在调查并缓解中”。
- 耐心等待。此类基础服务恢复可能需要几分钟也可能更久。若你的网站也挂了，建议先做降级处理或通知用户“正在恢复中”。

最后，作为网站运营者或内容创造者，也建议从今天这个事件里学到一点：**依赖越深，风险越集中**。即便使用云服务、CDN加速、防火墙保护，也不应忽视备用方案、冗余部署、用户提示机制。因为当“枢纽”失效，你依赖它的一切就可能“掉链子”。

**目前大部分服务都恢复了～ 如果你的服务还没有恢复，可能是地域性的问题，出去散散步，回来之后差不多就恢复了。**

总之，今天互联网“肠道”里出现一个短暂的“堵塞”，提醒我们：在这个看似“无处不在”的网络时代，也正是依赖与隐患并存。
